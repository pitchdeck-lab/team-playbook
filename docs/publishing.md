# 공개 발행 원칙

외부로 나가는 글에 적용합니다 — 테크 블로그, 외부 기고, 공개 발표, 컨퍼런스 자료.

사내 발표자료나 작업 기록에서 출발하는 경우가 많은데, 그대로 옮기지 않고
아래 기준으로 다시 씁니다. **옮기는 과정 자체가 검수 단계이므로 원본을 자동 동기화하지 않습니다.**

## 싣는 것

- 아키텍처와 설계 판단, 그리고 그렇게 정한 이유
- 공개 데이터의 수집 건수, 방법별 커버리지 같은 방법론 수치
- 막혔던 지점과 우회 방법

## 싣지 않는 것

- 내부 산출물 수치 (지표 값, 랭킹, 워치리스트)
- 거래처·고객사 실명, 사업자등록번호
- 내부 시스템 이름, 파일 경로, 사내 대화 원문
- 개인 실명 — 특히 데이터 오류 사례로 등장하는 인물은 반드시 익명 처리
- 소스 레포 링크. 코드 조각은 인용하되 레포는 공개하지 않습니다

## 애매할 때 — 세 가지 테스트

> **방법은 쓰고, 값은 상대값으로, 이름은 안 쓴다.**

### ① 재현 테스트 — 이 글만 보고 우리 걸 만들 수 있나?

없으면 대체로 공개해도 됩니다. 아키텍처·설계 판단·실패담은 공개해도 재현되지 않습니다.
반대로 룰셋 전체, 스코어 계산식, 매핑 테이블처럼 그대로 가져다 쓸 수 있는 것은 싣지 않습니다.
문제를 보여주는 코드 조각은 되고, 완결된 코드는 안 됩니다.

### ② 제3자 테스트 — 우리 말고 누가 손해 보나?

예외 없이 뺍니다. 고객사·거래처, 오류 사례로 등장하는 기업과 개인.
우리 잘못을 쓰는데 남의 이름이 같이 나갈 이유가 없습니다.

### ③ 회수 테스트 — 한 번 나가면 되돌릴 수 있나?

지표 값·랭킹·점유율은 회수가 안 됩니다. 애매하면 **상대값으로 바꿉니다.**

```
risk_score 최대값이 109.4 → 17.0 으로 떨어졌다     ✗
risk_score 최대값이 6분의 1 수준으로 떨어졌다       ✓
```

이야기는 그대로 남고 절대값은 나가지 않습니다.
